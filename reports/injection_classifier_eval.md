# Model-based injection detector (TF-IDF + logistic regression) on real data

Generated by `scripts/train_injection_detector.py` on 2026-11-20. Every number below is script output. 95% Wilson CIs. Detectors: `regex` = the shipped rule set (guardrails/injection.py); `classifier` = the model alone; `regex+classifier` = a sentence is redacted if either fires (what now ships).

## Protocol

- Train: 2499 dataset rows (1373 attacks) + 46 web pages (5224 unique visible blocks as benign). Validation: 641 dataset rows (357 attacks) + 18 web pages. Test: 746 dataset rows (434 attacks) + 26 web pages.
- Dataset rows: each dataset's own test split is TEST; its train(+validation) rows are split 80/20 into TRAIN / VALIDATION by a hash of the text. Real B2B pages are split BY PAGE (hash of URL) 60/20/20, so test pages are never seen in training or threshold selection.
- Model: TF-IDF word 1-2-grams (20k) + char_wb 2-5-grams (50k), sublinear tf, logistic regression (C=2.0, class_weight=None, training unit=sample, min 3 words per scored block). Hyperparameters chosen on validation from 24 configurations (max validation pooled-injection recall of regex+classifier at the threshold rule below); fitted on TRAIN only.
- Threshold rule (stated before looking at test): the lowest threshold at which regex+classifier redacts <= 0.5% of visible sentences on the VALIDATION pages. Chosen threshold: 0.201.
- TEST was scored once, through `quarantine()` itself (the same call the fetch tool makes). The regex rules were tuned earlier on all non-test rows (train+validation here), so regex numbers on validation are optimistic; test is clean for both.
- Artefact: `src/ai_sdr_crew/guardrails/injection_clf.json.gz` (587 KB gzipped JSON, 70000 terms; no pickle, no scikit-learn at runtime).
